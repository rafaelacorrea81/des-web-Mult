# Unidade 1 — O que é Controle de Versão

**Objetivo:** Explicar o que é um sistema de controle de versão e por que todo projeto de código deveria usar um, e diferenciar Git de GitHub sem confundir os dois.

## O problema que o controle de versão resolve

Imagine escrever um trabalho salvando arquivos como `trabalho_final.docx`, `trabalho_final_v2.docx`, `trabalho_final_v2_agora_vai.docx`. Funciona, mas é confuso, ocupa espaço e não deixa claro o que mudou entre uma versão e outra. Um sistema de controle de versão resolve exatamente esse problema, só que para código.

- **O que ele guarda:** um histórico completo de cada mudança feita nos arquivos do projeto, quem fez, quando fez e por quê (a mensagem do commit).
- **O que ele permite:** voltar a qualquer ponto anterior do projeto, comparar versões, trabalhar em paralelo com outras pessoas sem sobrescrever o trabalho alheio.

## Git x GitHub — não são a mesma coisa

Essa é a confusão nº 1 de quem está começando:

- **Git** é o **programa** que roda no seu computador e cria esse histórico de versões, localmente, mesmo sem internet.
- **GitHub** é um **serviço na nuvem** (um site) que hospeda esse histórico, permitindo compartilhá-lo, fazer backup e colaborar com outras pessoas. Existem alternativas ao GitHub, como GitLab e Bitbucket — o Git por trás é sempre o mesmo programa.

> 💡 **Analogia:** pense no Git como o motor que registra as mudanças no seu computador, e no GitHub como a garagem na nuvem onde uma cópia desse motor fica estacionada e visível para outras pessoas.
